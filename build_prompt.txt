# 10. Cross-cutting requirements

* **Routing:** lazy-loaded routes, a 404 page, route-level error boundaries, and `document.title` per page ("Upload · Knowledge AI").
* **Responsive:** verified at 360 / 768 / 1024 / 1440 / 1920px, with no overlap, clipping, or horizontal scroll. Tables scroll inside their own wrapper. The mobile sidebar is a drawer.
* **Accessibility:** WCAG AA in both themes, ember focus rings, labelled icon buttons, dialog focus trapping, status text never conveyed by color alone, and live regions for upload progress and streaming.
* **Performance:** virtualized lists, memoized rows, debounced inputs (250ms), prefetch on hover for collection and document routes, and a stable `queryKey` factory.
* **Security:** never render document text as raw HTML. Sanitize any markdown and highlight output, and validate file types by extension and MIME.
* **Design discipline:** keep the "Ink & Paper" rules: no gradients, glow, sparkle icons, or emojis. Ember is used only for primary actions, the active nav marker, citation markers, focus rings, and key chart series. Hairline borders, 6px control radius, 10px card radius.
* **No dead UI:** every button, menu item, and link must do something real or be removed. No "WIP", "Coming soon", or lorem ipsum anywhere.
